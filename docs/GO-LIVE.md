# Google 共用版上線

正式架構是 GitHub Pages 網站＋Google Apps Script 與私人試算表。同事在網站原生表單填寫及送出。冰箱不顯示餘量；免登入倉庫顯示數量，10 包／瓶／罐以內標紅。每次盤點／入庫都必填登記人。

正式網址為 <https://reytai-hldwn.github.io/pantry/>。既有網站要啟用原生送出，只需依 [更新 Google 部署](GOOGLE-SETUP.md#已有-google-部署更新原生表單) 更新原部署版本。以下開站設定供第一次部署或維護時參考。

## 1. 建立 Google 端

依 [Google 設定說明](GOOGLE-SETUP.md)，把 [Code.gs](../google-apps-script/Code.gs) 貼進自己的 Apps Script 專案，執行 `setupOnce` 授權建立私人試算表與五張表單。日常使用者不用設定管理帳號。

新版網站直接使用五種原生表單，不依賴 Google 表單的發布設定。飲料與零食統一在採買許願池，新增時必選類型、不用填姓名；「我也喜歡」贊同才必填姓名。原始試算表維持受限制，不必發布成公開 CSV。快速新增飲料必填品名、分類、包裝與登記人，圖片可稍後補；新飲料初始待盤點。

把 Apps Script 部署成「執行身分：自己；存取：任何人」的網頁應用程式，取得正式 `/exec` 網址。冰箱讀取公開品項與願望，管理入口另外讀取庫存及登記人紀錄。任何持有連結的人都可使用管理入口。

## 2. GitHub 開站設定

1. 程式放在 `reytai-hldwn/pantry` 的 `main` 分支。
2. GitHub 儲存庫 **Settings → Pages → Source：GitHub Actions**。
3. **Settings → Secrets and variables → Actions → Variables** 新增 Repository variable：

   | 名稱 | 值 |
   | --- | --- |
   | `GOOGLE_SCRIPT_URL` | 上一步的 `https://script.google.com/macros/s/…/exec` 網址 |

4. **Actions → Deploy Google-connected pantry to GitHub Pages → Run workflow**。
5. 等 `build` 與 `deploy` 成功，使用工作結果提供的 Pages 網址開站。

缺少 `GOOGLE_SCRIPT_URL` 時，部署工作會略過，不代表網站已發布。只改 Variables 不會自動啟動部署，須再執行 Run workflow。

建置會自動為樣式、腳本、公開設定及整個模組匯入鏈加上一致的版本參數。驗證更新時，先核對首頁 `pantry-release` 與實際載入的 CSS／模組版本；GitHub Pages 首頁本身仍可能有快取，可用 `/?update=<pantry-release>` 開啟該次更新，無須清除瀏覽器資料。需在保留舊快取的瀏覽器測試，不能只核對附加隨機查詢參數後下載的單一檔案。

這個網址是網站需要的公開資料入口，支援指定操作寫入，不是密碼或管理金鑰。不要把 Google 密碼、OAuth 權杖或其他秘密填進 GitHub Variables。流程不會改變儲存庫可見性；若私人儲存庫的方案不支援 Pages，需由儲存庫擁有者處理。

## 3. 正式驗證

- 定稿外觀：桌機左側白底工具列、右側使用空間原照重繪的辦公室四門冰箱，長桌兩側成排木椅、桌面延伸至右側，電視沒有中央亮面，冰箱不放便條貼；手機保留原本單門冰箱。關門看不到搜尋及分類，開門拉近後才顯示，飲料沿用真實商品圖。
- 桌機依視窗比例使用橫幅或窄高插畫，保留電視、窗景及兩側椅子；左側小型雲朵框顯示「點擊打開冰箱」，不帶尖角尾巴，旁邊短小的手繪迴圈箭頭指向門片。箭頭與框的咖啡金描邊、暖白填色及柔和陰影需一致。拖曳視窗後，框仍完整可見且箭頭對齊；點標示或門均可開啟。一般動態下四扇門打開、露出有飲料的層架，並連續拉近完整飲料架，約 0.65 秒完成，不能停在白色方塊；搜尋隨後顯示。測試中途關門再重開，確認不會被舊計時器打開。減少動態設定可直接開啟，關門後標示恢復。手機不載入桌機插畫，維持既有操作。
- 背景同步或按「重新整理」等候 Google 回應時，仍可由飲料冰箱切換歷史品項、許願池或管理頁面。較晚回來的回應不會切回舊頁面或清除正在填寫的內容。同一區域內切換不需要重新等待同一份資料；切換前台／倉庫時會顯示讀取狀態。
- 用未登入的手機開網站：32 款飲料、牛奶／豆漿最上層，點門才能往下滑，頁面不顯示餘量。
- 手機關門不下載飲料照片；回訪先顯示上次已驗證的公開清單並背景更新，初次使用或快取過期時讀取 Google。開門後熱門榜獨立讀取，不阻擋搜尋或切頁；至少兩次實際盤點且有效間隔滿一天才顯示平均每週飲用量，紀錄不足顯示「累積盤點中」。
- 歷史區有 8 款停買品項；停買品項不進入目前供應、盤點或到貨品項選單。之後可重新上架並保留原本紀錄。
- 後台庫存的泡麵與碳粉以獨立工作表儲存，不進入飲料冰箱與人氣排名。六款泡麵以杯／碗登記（辛拉麵用杯），四色碳粉以盒登記，沒有整箱欄位。新版 Google 部署啟用前，顯示「待盤點」與更新提示；啟用步驟見 [泡麵與碳粉設定](SUPPLIES-SETUP.md)。
- 到貨入庫分為飲料、泡麵、碳粉三個子頁；選單依紀錄庫存由少到多，待盤點排後，不標示需要補貨。飲料與泡麵的「其他／新品」需最新 Apps Script 部署，建立品項與到貨共用儲存回條；泡麵效期必填。確認同名與重複送出不重建品項，新品下次可直接選取，三類最近紀錄各自顯示。
- 既有泡麵可在倉庫「補登效期」，各批合計須等於現有庫存；過期日期可如實補上，不增加入庫或盤點數量。核對跨裝置過期輸入會被拒絕、重複送出不多建批次、提醒依最新效期核對更新且舊紀錄保留。舊 Google 部署暫停此新操作，原盤點與入庫保持可用。
- 庫存與匯出由少到多、待盤點排後。勾選暫不補貨或準備替換後，品項保留在 10 以內清單、飲料數量改一般字色，待補貨數與複製清單排除此項；取消即恢復。確認另一個瀏覽器可讀取設定，且數量、盤點、入庫及泡麵效期不變。設定首次寫入自動建立 `RestockPreferences`，舊部署暫停勾選並顯示更新說明。
- 泡麵每次入庫必填保存期限，分別保留各批次；30 天內近效期、當日及已到期有提示。確認某批已用完可結束該批提醒，數量另以盤點校正；盤點為零則結束之前批次的提醒，原始紀錄仍保留。
- 在網站管理入口快速新增未出現過的飲料；送出後更新飲料架，手機 B 也能看到示意圖，新飲料出現在盤點及到貨選單、初始待盤點；重送同品名不重複新增，舊品項與數量不變。
- 在手機 A 分別匿名送出飲料、零食願望，手機 B 重新整理後能在採買許願池的「全部」看到兩類，切換分類時只顯示對應願望。
- 按「我也喜歡」時必須填姓名；原生表單儲存確認後人數才增加，同一瀏覽器對同一願望重複送出不加票。點人數可查看贊同者姓名，移過人數可預覽。
- 未登入的手機可使用管理入口，五種操作都在網站內填寫及送出，不開啟 Google 表單或新分頁；盤點及入庫未填登記人不可送出。異動紀錄顯示填寫的稱呼。
- 倉庫初始顯示待盤點。只盤一項 20、其他留白，其他品項及時間不變；後續入庫只填零散 12，該項變 32；再盤點 0，該項變 0 並標紅。只填整箱 1 會加 24，整箱 1 加零散 3 會加 27。全空白盤點或入庫不計入庫存。
- `Catalog` 取消 active 後，品項移到歷史區；原本歷史和庫存仍保留。重新上架後回到原分類。

上面的匿名填寫與跨手機結果尚未在真實 Google 環境測試；本機及模擬測試通過，不能取代這次正式驗證。

贊同送出前會告知姓名顯示在贊同名單。驗收時請確認桌面移過人數可預覽、手機點人數可開啟名單，且舊票缺少姓名時不會被清除。
