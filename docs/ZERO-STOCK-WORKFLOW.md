# 無庫存處理

後台總覽的「無庫存」維持預設收合，僅包含有實際數量紀錄且為 0 的飲料、零食與泡麵。碳粉仍在原低庫存提醒，不新增無庫存分類；尚未盤點不當作 0。

展開後分為「待處理」與「待補貨」。選擇「加入待補貨」會儲存共用狀態及補貨標記；可以取消，回到待處理。此處加入的待補貨，在該品項單筆或批次到貨入庫後自動結束。一般從倉庫勾選的人工補貨標記，仍保持原本由人取消的規則。

「移至歷史品項」只改供應狀態，保留同一個 ID、庫存、口味、效期及異動紀錄，同時解除本次補貨標記。飲料可在前台歷史品項及倉庫歷史清單查看；零食與泡麵可在各自倉庫的「歷史品項」查看。再次到貨時從入庫選單或倉庫歷史列選原品項，送出後恢復供應，不建立重複品項。

處理時伺服器會再確認庫存仍為 0、仍在供應中，以及原補貨狀態。若庫存紀錄或其他裝置的決定已改變，會要求重新讀取。重試沿用原請求 ID，不重複建立入庫或補貨事件；已確認的操作以回條更新總覽，避免再下載完整倉庫紀錄。

總覽的低庫存說明為：

> 飲料 10包/瓶/罐以下 · 零食與泡麵評估餘量少且已勾補貨 · 碳粉無剩餘庫存時，會列在這裡

飲料與零食的量少區間仍為 1–10，泡麵為 1–3；總覽中的零食及泡麵都需已勾選補貨。0 另列無庫存，碳粉維持 0 盒才提醒。

## 啟用與相容性

前台文字、可爾必思簡稱與分類可隨網站更新生效。共用的無庫存處理需把此版 `google-apps-script/Code.gs` 全文替換至原 Apps Script 專案，儲存後選「部署 → 管理部署 → 原部署的鉛筆 → 新版本 → 部署」。不用執行 `setupOnce`、更換網址或重新建立工作表。

可以先保留新版程式，等方便時再更新原部署。舊部署仍可讀取資料，處理按鈕顯示為尚未啟用，不會把本機狀態誤當成已共用。新部署會回傳 `zeroStockVersion: 1`，前台才啟用操作。

待補貨沿用 `RestockPreferences`，以操作來源 `zero-stock:pending` 區分這次待補貨與一般人工勾選；不新增數量欄位或虛構盤點。狀態處理及歷史入庫均沿用原請求回條和補貨事件去重機制。
