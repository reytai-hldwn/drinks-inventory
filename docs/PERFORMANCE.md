# 手機載入與飲用人氣

## 載入方式

- 手機沿用原單門插畫的相同 347 × 475 像素區域，抽出為無損 WebP，提早載入；不再為該區域下載完整設計稿。
- Logo 使用正式原檔產生的 160 像素顯示副本，圖示另用 64 像素副本；原檔保留。
- 飲料架與桌機開門內景使用顯示尺寸 WebP，剪影與裁切座標沿用原照片；飲料詳細資訊仍使用原檔。
- 關門不指定飲料照片的 `src`；開門才啟用原生延遲載入。
- `pantry-ui.woff2` 包含目前介面與品項用字，罕用新字仍可依需要使用完整字型。
- 已驗證的公開清單最多保留 24 小時，回訪先顯示上次資料並背景重讀 Google。快取綁定部署網址；倉庫數量、盤點紀錄不寫入這份快取。快取過期、格式有誤或瀏覽器不允許儲存時，正常讀取 Google。

顯示素材可用 `node scripts/build-display-assets.mjs` 重建，需要 ImageMagick、fontTools 與 Brotli；產物已提交，正式 CI 不需要這些額外工具。所有原始圖檔仍保留。

## 量測

2026-11-02 本機瀏覽器對照：390 × 844、CPU 4 倍降速、80 ms 網路延遲、750,000 bytes/s 下載、Google 回應模擬為 1.5 秒。每次皆使用空快取，關門後等候 6 秒，再開門等候 4 秒。

| 指標 | 優化前 | 優化後 |
| --- | ---: | ---: |
| 關門階段已完成傳輸 | 3,958,799 bytes | 806,380 bytes |
| 開門階段累計已完成傳輸 | 8,356,633 bytes | 1,141,778 bytes |
| 手機背景單一資源下載時間 | 9,475 ms | 993 ms |

關門傳輸減少約 80%。這些是指定條件下的資源量測，不是每台手機的開站時間保證。首次使用仍須等待 Google 回應；回訪快取的整合測試會刻意扣住 Google 回應，確認清單可先顯示並操作。

## 熱門飲料

冰箱內上方顯示前三名與「平均每週」。計算方式是相鄰兩次盤點間的「前次盤點＋中間入庫－本次盤點」，除以觀察天數後乘以 7。依容器數排名，單位保留包／瓶／罐；不是本週逐次取用紀錄，也不是銷售額或點閱次數。

至少兩次盤點、有效間隔合計滿一天，才顯示估算；未記錄入庫造成的負消耗、異常與停買品項不參加排名。沒有足夠紀錄時顯示「累積盤點中」，有效紀錄為零消耗時不列假排名。

統計在第一次開門後獨立讀取既有 `warehouse` 端點，不改變目前頁面、公開清單或管理狀態；只保留計算後的摘要，5 分鐘內重開沿用。盤點、入庫或新增品項成功後使摘要過期。這次沿用現有 Apps Script 部署。

整合測試 `tests/browser-mobile-performance.mjs` 驗證關門零飲料照片下載、正確扣除入庫、統計等候時可搜尋與切頁、回訪先顯示清單，以及背景回應保留未送出表單。
