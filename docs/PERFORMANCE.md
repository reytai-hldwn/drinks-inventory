# 網站載入、送出與飲用人氣

## 載入方式

- 手機沿用原單門插畫的相同 347 × 475 像素區域，抽出為無損 WebP，提早載入；不再為該區域下載完整設計稿。
- Logo 使用正式原檔產生的 160 像素顯示副本，圖示另用 64 像素副本；原檔保留。
- 飲料架與桌機開門內景使用顯示尺寸 WebP，剪影與裁切座標沿用原照片；飲料詳細資訊仍使用原檔。
- 關門不指定飲料照片的 `src`；開門才啟用原生延遲載入。
- `pantry-ui.woff2` 包含目前介面與品項用字，罕用新字仍可依需要使用完整字型。
- 已驗證的公開清單最多保留 24 小時，回訪先顯示上次資料並背景重讀 Google。快取綁定部署網址；倉庫數量、盤點紀錄不寫入這份快取。快取過期、格式有誤或瀏覽器不允許儲存時，正常讀取 Google。

顯示素材可用 `node scripts/build-display-assets.mjs` 重建，需要 ImageMagick、fontTools 與 Brotli；產物已提交，正式 CI 不需要這些額外工具。所有原始圖檔仍保留。

## 量測

2026-11-02 本機瀏覽器對照：390 × 844、CPU 4 倍降速、80 ms 網路延遲、750,000 bytes/s 下載、Google 回應模擬為 1.5 秒。每次皆使用空快取，關門後等候 6 秒，再開門等候 4 秒。

| 指標 | 優化前 | 優化後 |
| --- | ---: | ---: |
| 關門階段已完成傳輸 | 3,958,799 bytes | 806,380 bytes |
| 開門階段累計已完成傳輸 | 8,356,633 bytes | 1,141,778 bytes |
| 手機背景單一資源下載時間 | 9,475 ms | 993 ms |

關門傳輸減少約 80%。這些是指定條件下的資源量測，不是每台手機的開站時間保證。首次使用仍須等待 Google 回應；回訪快取的整合測試會刻意扣住 Google 回應，確認清單可先顯示並操作。

## 熱門飲料

冰箱內上方顯示前三名與「平均每週」。計算方式是相鄰兩次盤點間的「前次盤點＋中間入庫－本次盤點」，除以觀察天數後乘以 7。依容器數排名，單位保留包／瓶／罐；不是本週逐次取用紀錄，也不是銷售額或點閱次數。

至少兩次盤點、有效間隔合計滿一天，才顯示估算；未記錄入庫造成的負消耗、異常與停買品項不參加排名。沒有足夠紀錄時顯示「累積盤點中」，有效紀錄為零消耗時不列假排名。

新版統計在第一次開門後獨立讀取 `popularity` 摘要端點；舊部署沿用 `warehouse` 端點，不改變目前頁面、公開清單或管理狀態；只保留計算後的摘要，5 分鐘內重開沿用。盤點、入庫或新增品項成功後使摘要過期。端點網址沿用原部署；完整改善需更新 Code.gs 並發布原部署的新版本。

整合測試 `tests/browser-mobile-performance.mjs` 驗證關門零飲料照片下載、正確扣除入庫、統計等候時可搜尋與切頁、回訪先顯示清單，以及背景回應保留未送出表單。


## 桌機、後台與送出流程（2026-11-02）

- 桌機兩種原尺寸插畫改用品質 90 的 WebP；橫幅由 2,316,448 bytes 降為 234,416 bytes（約少 90%），窄高版由 2,249,839 bytes 降為 210,332 bytes。原始 PNG 保留。桌機首頁預先下載常見橫幅，手機與其他入口不下載桌機插畫。
- 同類資料的重疊讀取共用同一請求；已確認寫入後，較早發出的讀取不能蓋掉新資料。從後台返回前台可立即使用剛驗證的公開欄位，再背景重讀；不把庫存與紀錄保留在公開快取。
- 後台總覽入口立即顯示，低庫存摘要獨立讀取 `admin`。摘要含飲料、泡麵、碳粉的 10 以內品項、暫不補貨狀態與願望待評估數；不開啟 Google Forms、不讀取投票名單、不傳回整份紀錄。不足資料的品項不當作 0。僅記憶體保留 15 秒，庫存寫入後失效。舊部署自動以原倉庫端點相容讀取。
- 許願／贊同不再計算、重畫庫存工作表。伺服器完成持久儲存後，回條帶回該筆願望與票數；網站驗證目標和欄位後直接更新，省下一次完整清單讀取。很大的贊同名單或舊部署沿用完整重讀。
- iframe 回應載入可以提早查詢回條；載入本身不代表成功。回條確認、固定請求 ID、防重複與超時後保留原輸入的規則仍保留。
- 固定表單網址依表單 ID 在 Script Cache 暫存 6 小時；完成回條也可暫存。沒有快取仍以來源資料處理，未完成的回條不快取。庫存、願望與原始紀錄不做伺服器資料快取。原生飲料寫入只在會影響已封存品項的重試中重畫封存工作表。

受控 Chromium 對照（虛構資料，POST 延遲 400 ms、回條 200 ms、公開讀取 1,200 ms）：

| 流程 | 原桌機 | 新桌機 | 原手機 | 新手機 |
| --- | ---: | ---: | ---: | ---: |
| 送出許願至畫面更新 | 3,033 ms | 1,429 ms | 2,913 ms | 998 ms |
| 贊同至畫面更新 | 3,193 ms | 1,262 ms | 2,923 ms | 1,019 ms |
| 後台返回冰箱 | 1,509 ms | 92 ms | 1,402 ms | 70 ms |

同一流程完整資料讀取由 5 次降為 3 次。這是相同模擬條件的流程比較，不包含真實 Apps Script 的啟動時間保證。正式端點唯讀單次基線約為公開 7.85 秒、倉庫 6.22 秒、未完成回條 2.34 秒；因此省去整份重讀有實際價值，Google 本身回應較慢時仍需等候。

`tests/performance.test.mjs` 驗證來源工作量、回條快取提交順序、過時回應保護、統計同算法與獨立摘要；`tests/browser-performance.mjs` 可設 `PANTRY_BASELINE_ROOT` 對照舊版。`tests/browser-admin-archive.mjs` 驗證總覽不等候完整紀錄、10 以內優先、暫停補貨的一般字色，以及歷史品項回購的共用票數。
