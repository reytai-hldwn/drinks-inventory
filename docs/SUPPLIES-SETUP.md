# 啟用泡麵、碳粉庫存、保存期限與新品入庫

網站後台分成「飲料／泡麵／碳粉」。泡麵與碳粉存放在原試算表的獨立工作表，沿用目前 Google Apps Script 部署網址；原飲料、願望及其紀錄繼續使用。

## 1. 更新原 Apps Script 專案

1. 開啟 [最新版 Code.gs](https://github.com/reytai-hldwn/pantry/blob/main/google-apps-script/Code.gs)，按 **Raw** 開啟純文字，按 `Ctrl+A`、`Ctrl+C` 複製完整內容。
2. 到 [Google Apps Script](https://script.google.com/home)，開啟目前提供網站 `/exec` 網址的原專案。
3. 左側選 **Code.gs**，按 `Ctrl+A` 全選、`Ctrl+V` 貼上，再按 `Ctrl+S` 儲存，等畫面顯示已儲存。
4. 這次不需執行 `setupOnce`。原專案的 Script Properties、原試算表及部署網址會繼續使用。

## 2. 更新目前正在使用的部署

1. 右上角按 **部署 → 管理部署**。
2. 左側選目前網站正在使用的「網頁應用程式」部署。
3. 按右側的 **鉛筆圖示（編輯）**。
4. **版本**選擇 **新版本**，說明可填「分類到貨、新品入庫與泡麵保存期限」。保留原執行身分與存取設定。
5. 按 **部署**；若 Google 要求授權，使用原帳號完成。
6. 沿用原本的 `/exec` 網址，不必更改 GitHub Variables。

只按儲存不會更新網站呼叫的正式版本，需完成上述「管理部署 → 新版本 → 部署」。

## 3. 回網站確認

1. 開啟 [宏穩茶水間](https://reytai-hldwn.github.io/pantry/)，按 **管理後台 → 倉庫庫存**。
2. 點 **泡麵** 或 **碳粉**。若仍顯示更新提示，按網站右上角 **重新整理**，再確認上一節已更新正確的部署。
3. 下列品項先顯示「待盤點」，沒有預填現有數量：

   | 分類 | 品項 | 單位 |
   | --- | --- | --- |
   | 泡麵 | 來一客海鮮 | 杯 |
   | 泡麵 | 滿漢大餐牛肉麵 | 碗 |
   | 泡麵 | 拉麵道味噌拉麵 | 杯 |
   | 泡麵 | 拉麵道豚骨拉麵 | 杯 |
   | 泡麵 | 奶油白醬辣火雞麵 | 杯 |
   | 泡麵 | 辛拉麵 | 杯 |
   | 碳粉 | 黑色碳粉 | 盒 |
   | 碳粉 | 黃色碳粉 | 盒 |
   | 碳粉 | 紅色碳粉 | 盒 |
   | 碳粉 | 藍色碳粉 | 盒 |

4. 實際清點後，按單一品項的 **盤點**，或上方 **盤點這一類**；填登記人與實際數量。空白保留原紀錄，填 `0` 才代表實際為零。
5. 第一次成功登記時，原試算表會自動新增 `SupplyCatalog`、`SupplyHistory`、`SupplyWarehouse`。前兩張是來源資料，後者是產生的庫存檢視；查閱清單不會建立或改寫紀錄。

## 4. 快速入庫與保存期限

「到貨入庫」分成 **飲料／泡麵／碳粉** 三個子頁，每頁各有入庫表單與最近五筆該類入庫紀錄。可從頁面上方切換，或直接開啟 [泡麵到貨入庫](https://reytai-hldwn.github.io/pantry/#restock-noodle)、[碳粉到貨入庫](https://reytai-hldwn.github.io/pantry/#restock-toner)。泡麵與碳粉沿用庫存頁的相同儲存與效期紀錄；未儲存時切換會先提醒。

三個入庫選單依目前紀錄庫存由少到多排列，待盤點的品項排在後方；選單顯示數量，不標記「需要補貨」。飲料與泡麵的「其他／新品」固定在最後。

1. 點品項旁的 **＋ 快速入庫**。
2. 填登記人與本次到貨數量，依該品項的「杯／碗／盒」登記。兩類均不使用整箱換算。
3. **泡麵必填保存期限**，以包裝上的有效日期為準；不能填早於今天的日期。碳粉不需填保存期限。
4. 相同品項若有不同保存期限，分次入庫。每次都會保留自己的批次、原入庫量、日期、登記人及備註，新日期不覆蓋舊批次。
5. 按 **確認入庫**，收到 Google 儲存確認才顯示成功。

總庫存＝最近一次實際盤點＋之後到貨。尚未完成首次盤點時，入庫仍會保存，但總量繼續顯示「待盤點」，不會把未知的原庫存當成零。

## 5. 查看效期提醒

- 泡麵庫存表的 **保存期限／入庫批次** 欄顯示較早的保存期限；展開可查看各批次。
- 預設 **30 天內到期**顯示近效期提示；當日顯示「今天到期」，超過日期顯示「已到期」。判斷以台北日期為準。
- 批次上顯示的是原入庫數量，實際剩餘需現場核對。
- 確認某批已用完或已移除後，按 **此批已用完**、填登記人，再確認，可解除該批提醒。這個標記保留紀錄，總庫存另以實際盤點校正。
- 當實際盤點為 `0` 時，之前各批次的提醒自動結束；原入庫與效期紀錄仍保留。
- 既有庫存沒有保存期限資料時顯示「效期待補」，不推測日期。
- 若盤點既有庫存或上調數量時沒有對應的入庫效期，另顯示效期待核對提示；新入庫的日期不代表舊庫存也已核對。

## 6. 到貨時登記新品

1. 在飲料或泡麵到貨子頁，從品項選單選 **其他／新品**，即可展開品項名稱與單位欄位。碳粉維持固定四色。
2. 填完整品名與口味；飲料選包／瓶／罐，泡麵選杯／碗。新品先按單位填實際到貨量，不做整箱換算；泡麵仍必填保存期限。
3. 填登記人並確認送出。新品與這次到貨使用同一份儲存確認及重試識別碼，重複點擊不會多建品項或多計到貨。
4. 成功後，新品會留在選單及倉庫供後續使用。同名品項需沿用原選項；已停買品項請先核對歷史清單，避免庫存拆成兩份。
5. 新品總庫存先標示待首次盤點，本次到貨量與泡麵效期已保存。實際盤點確認現場總量後，後續到貨才加在該數量上。
6. 新飲料先使用包裝示意圖，分類與包裝暫記「其他」、每箱數量待設定，圖片與營養資訊可之後補齊。後續更新既有品項資料時，沿用它在試算表的 ID，不再重建同名品項。

若已完成上一版泡麵與碳粉更新，這次仍需按第 1、2 節替換最新版 `Code.gs` 並部署新版本，才能使用「其他／新品」。更新前原有入庫繼續使用，新品選項顯示更新提示並暫停選取。

## 7. 補登既有庫存的保存期限

盤點先記下實際數量後，可在 **倉庫庫存 → 泡麵 → 品項旁「補登效期」** 補上現場批次的保存期限，不必再登記一次入庫。

1. 先完成該品項的實際盤點，庫存需大於零。尚未盤點或實際為零的品項不開放補登。
2. 按 **補登效期**，填登記人、每批數量與保存期限。若有不同日期，按 **新增一批** 分開填寫；一次最多 20 批。
3. 各批數量合計必須等於目前庫存。若現場總量不同，先重新盤點；補登不會增減庫存，也不會新增到貨或盤點紀錄。
4. 日期依實物包裝填寫；既有庫存可補登已過期日期，系統會如實顯示到期狀態。
5. 儲存後依本次現場核對結果更新該品項全部效期提醒，過去入庫、盤點及效期紀錄仍保留；批次標示「效期核對」及核對當時數量。之後新到貨繼續保留自己的批次。
6. 若另一裝置在填寫期間更新這個品項，系統會保留輸入並拒絕覆蓋；重新整理並核對現場後再填寫。

此功能需要最新版 Google 部署。先依第 1、2 節更新原專案與原部署；無須執行 `setupOnce`。更新前「補登效期」停用，既有盤點與入庫繼續使用。

## 8. 庫存排序與暫不補貨

- 飲料、泡麵、碳粉的庫存與匯出清單皆由少到多，數量為零排前面，待盤點排最後。同數量維持原順序，品項與原紀錄不重排或刪除。
- 三個庫存子頁都有 **10 以內** 清單；依已盤點的目前數量篩選，未盤點不當作零。
- 在低庫存品項勾選 **暫不需要補貨**，會立即儲存到共用試算表；儲存期間暫停其他勾選，成功後其他裝置重新整理也看得到。
- 勾選後可按 **改標為準備替換新品項**，顯示「可以準備替換新品項」；也可再改回「暫不需要補貨」。這是補貨標示，品項仍維持供應中。
- 已暫緩的品項若仍在 10 以內，依舊留在清單，飲料庫存不顯示紅字，也不列入待補貨數與複製補貨清單。泡麵保存期限及到期提示照常顯示。
- 取消勾選可恢復一般提醒。設定會持續保留，即使後來入庫超過 10，也能取消；數量、盤點時間、入庫與效期紀錄均不受影響。
- 首次明確勾選時才建立 `RestockPreferences`，以追加紀錄保存設定及操作來源；查閱清單不建立或改寫此表。設定使用原有儲存回條與防重複提交流程。

此功能需要最新版 `Code.gs` 與原部署的新版本。更新前排序仍可使用，勾選停用並顯示說明；不用建立新專案、換網址或執行 `setupOnce`。

這次 Google 端更新需由專案擁有人完成；網站程式無法替你發佈 Google 帳號內的 Apps Script 部署。更新前，飲料流程繼續運作，泡麵與碳粉顯示品項與明確提示，新增儲存功能暫不開放。


## 零食入庫與分類

到貨入庫與倉庫大類依序為「飲料／零食／泡麵／碳粉」。零食分類為：太空包、巧克力、甜/鹹餅乾、燕麥棒/餅、其他鹹食、其他甜食。四款起始商品為多力多滋雙倍起司口味、多力多滋香菜口味、樂事海苔口味、華元蚵仔煎，全部先以太空包、包為單位，庫存待盤點。

零食到貨頁先選分類或輸入品牌、口味、品名，選單即時縮小範圍；這些篩選只使用已讀取資料，不額外呼叫 Google。選不到商品時按「找不到商品？新增零食」，搜尋文字與已選分類會帶入新品欄位，填好單位、數量、保存期限與登記人後一次儲存。單位支援包、盒、條、個、顆；不同期限分次登記。同名檢查忽略大小寫、全半形及頭尾空白差異，拒絕重複新品時保留輸入。搜尋或切換分類不會默默新增商品，也不會清空已填數量、效期及登記人。

零食每個口味分別保留庫存與效期，按數量由少到多、待盤點放最後；不顯示單一口味低庫存紅字、補貨勾選或總覽補貨推薦。到期與 30 天內到期提醒維持。泡麵、飲料及碳粉的原有補貨設定不變。

Google 端透過 `supplyEntry.snackVersion=1` 啟用；舊部署仍可操作原品項，零食入庫提示更新。只需要把這次完整 `Code.gs` 更新到原部署的新版本，不執行 `setupOnce`、不改網址。前次效能、回購與登記人更正能力都包含在同檔案，之後部署用這份最後版本即可。

`SupplyCatalog` 第六欄 `category` 保存零食分類，其他種類仍保留原五欄資料。讀取新部署不修改工作表；第一次實際零食／用品寫入才補入必要標題與品項。第六欄已有其他用途時拒絕寫入，避免覆蓋。新品與到貨使用相同請求 ID 重試，來源數量、既有批次和其他商品不會被重置。
