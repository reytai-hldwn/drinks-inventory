# 用 Google 表單與試算表正式共用

冰箱只顯示飲料與願望；「管理後台」免登入，可以快速新增飲料、查看倉庫、盤點及登記入庫。新增飲料與兩張庫存表單都必填「登記人」，Google 自動留下時間。任何拿到連結的人都可登記，姓名／暱稱由填寫者自行提供。數量 **10 個以下（含 10）標紅**。

Google 試算表與原始回應仍維持私人，網站透過唯讀資料網址顯示需要的內容。網站沒有公開編輯原始試算表的功能。以下操作需要由 Google 專案擁有人完成一次授權；程式備妥不代表資源已建立或網站已上線。

## 1. 建立 Apps Script 專案

開啟 [Google Apps Script](https://script.google.com/)，新增專案，將 [`google-apps-script/Code.gs`](../google-apps-script/Code.gs) 完整貼入 `Code.gs`。

日常使用不需要填 `ADMIN_EMAILS`，也不用為同事建立帳號。若要執行先前實際盤點的私人批次匯入，再於自己的 Apps Script 中填入擁有人 Google 帳號；不要把實際帳號、盤點數量或匯入資料提交到公開 GitHub。

程式包含 32 種目前供應飲料，另有 8 種停買的歷史品項：愛之味純濃燕麥、光泉燕麥奶、雪碧、紅牌蜂蜜奶茶、立頓蜂蜜紅茶、蘋果西打、克寧草莓優酪乳、愛之味麥仔茶。每箱數量留白，實際庫存保持待盤點。歷史品項預設 `active = FALSE`，不列入盤點或到貨選單。新飲料可從網站管理入口直接填寫新增；進階修改及恢復歷史品項仍以私人試算表的 `Catalog` 為準。

## 2. 執行 `setupOnce`

執行並同意 Google 表單／試算表存取授權，執行紀錄會提供私人試算表入口。它會建立：

- `Warehouse`、`Archive`：目前及歷史品項的數量檢視，刷新不會刪除來源紀錄。
- `Catalog`：品項、包裝、每箱數量、提醒門檻與啟用狀態。停買時將 `active` 改為 `FALSE`，保留舊列。
- `History`：盤點、到貨、登記人、收件時間與採計結果。請保留歷史列。
- `WishReview`：匿名願望、許願分類（`drink`／`snack`）與採購狀態（`pending`、`purchased`、`declined`）；舊願望未填分類時視為飲料。
- `WishVotes`：贊同回應、必填姓名與瀏覽器識別碼；識別碼用於去重，姓名及識別碼不送到網站願望卡。
- `ProductIntake`：快速新增飲料的原始回應 ID、登記人與採計結果，不包含虛構庫存；重送不會重複建立同一品項。
- `Setup`：五張 Google 表單入口；Google 自動產生的原始回應分頁也保留。

五張表單為「完整盤點」「到貨入庫」「採買許願池」「我也喜歡」「快速新增飲料」。許願不用填姓名，必填許願分類；贊同才必填姓名。網站統一使用「採買許願池」，在頁內篩選全部／飲料／零食。新增願望必須先選擇類型，再預填至 Google 表單。盤點一次填完全部啟用品項；到貨表單只填實際收到的單包／瓶／罐數量。未填登記人、漏填盤點或無效數量不計入庫存。

「快速新增飲料」在網站內嵌表單填寫品名、分類、包裝與登記人。實際送出並同步後才出現在冰箱、盤點及入庫選單；沒有圖片時自動用包裝示意圖。新飲料先顯示待盤點，每箱數量留白，不會自動增加庫存。品名與既有品項重複（忽略頭尾空白、英文字母大小寫及全半形差異）時不建立新列，請沿用原品項。日後補圖沿用相同品項 ID，保留庫存與歷史。

先前已設定過舊版的人，重新貼上最新版程式並執行 `setupOnce`。這會補上快速新增飲料表單與採計紀錄、登記人、許願分類、贊同姓名與新增的歷史品項、開放收件。`WishReview` 的分類接在第 7 欄，`WishVotes` 的姓名接在第 6 欄，既有欄位、願望問題 ID、已採計贊同、舊品項、庫存及歷史都保留；原本已採計的匿名贊同不會被取消。原先「點心」分類仍可正常讀取，新表單顯示「零食」。完成後也要重新部署 Apps Script 最新版本；舊版缺少分類或姓名欄位時，網站會停用相應送出入口並提示更新。曾經手動重新上架或修改過的品項也不會被覆寫。舊版 `enablePrivateForms` 函式僅作相容入口，不再要求登入或驗證 Email。

## 3. 將五張表單發布給任何人

在每張表單的發布／管理填答者設定允許「任何人」填寫。確認不收集 Email、不限制每人一次、不限定公司網域或 Google 登入。程式已關閉 Email 收集與每人一次限制，但 Google 帳號／組織的發布權限仍須由擁有人確認；公司政策若禁止匿名表單，需由 Google Workspace 管理員調整。

整份試算表保持「受限制」，只分享給要維護原始資料的人。**不用把試算表發布為 CSV，也不用開放任何人編輯試算表。** 網站管理入口的庫存及登記紀錄本身可由持連結者讀取。

「我也喜歡」按鈕先要求填寫姓名，再開啟預填姓名、願望代號與瀏覽器識別碼的表單；在 Google 表單送出後才登記贊同。不要修改願望代號或識別碼。新贊同未填有效姓名不採計，姓名會顯示在可點開的贊同名單；它仍由填寫者自行提供，不是登入驗證。同一瀏覽器以同一個願望＋識別碼只計一票，不要求登入；清除瀏覽器資料或換裝置會產生新的識別碼。

## 4. 發布資料網址並接到網站

在 Apps Script 選「部署 → 新增部署 → 網頁應用程式」，執行身分選「自己／專案擁有者」，存取者選「任何人」。複製結尾 `/exec` 的網址作為網站 `googleScriptUrl`。

修改程式後，在「管理部署」建立新版本；既有 `/exec` 網址可沿用。Google 部署完成後，仍須依 [網站上線步驟](GO-LIVE.md) 發布 GitHub Pages。

資料介面只有讀取：

- `/exec?action=public&callback=holdwinCallback`：品項、願望、贊同數、五張表單入口。飲料不含庫存數量或異動紀錄。
- `/exec?action=warehouse&callback=holdwinCallback`：倉庫數量、最近盤點與已採計的異動／登記人。免登入，但不含管理帳號、匿名識別碼或原始回應。

兩種回應都提供願望的 `kind`（`drink`／`snack`）、`wishForm: { url, kindEntryId }` 及 `voteForm: { url, wishEntryId, voterEntryId, voterNameEntryId }`，供網站預填分類及贊同欄位。這些欄位代號不是 Form 內部問題 ID；程式會用預填網址取得正確代號。只有 Google 表單收取新增資料；沒有公開 `doPost` 寫入 API。`updatedAt` 是同步時間，不代表自動追蹤日常取用。

`formUrls.product` 是可內嵌的快速新增飲料表單網址；舊版未建立此表單時為空字串。`ProductIntake` 的登記人與原始回應不會放入公開資料。

## 5. 用未登入 Google 的手機實測

- 開啟冰箱不顯示餘量；管理入口可查看倉庫、打開盤點與到貨表單，均不用登入。
- 空白登記人不能送出；有效盤點／入庫後，管理紀錄要有登記人、時間與數量。
- 在網站快速新增一款未出現過的飲料，不必上傳圖片；送出後更新飲料架，確認新飲料用示意圖出現，盤點及入庫表單可選到它。重新整理或重送同品名不會建立第二款，既有庫存及歷史不變。
- 盤點 20、之後到貨 12，庫存為 32；再盤點 7，庫存以 7 為準並標紅，不重加舊到貨。首次盤點前顯示待盤點。
- 在採買許願池分別匿名新增飲料、零食願望；重新整理後，「全部」顯示兩類，分類篩選只顯示對應願望。兩種許願均必選類型、不要求姓名。
- 按「我也喜歡」時，空白姓名不可繼續；填姓名並實際送出 Google 表單後，重新整理看到票數增加。同一瀏覽器重送同一願望只計一票；點人數可查看贊同者姓名，移過人數可預覽。
- 許願／贊同不更動庫存或採購狀態；停用品項及其歷史仍保留，恢復啟用不需重建。

表單觸發器會更新倉庫與願望，可能需等幾秒再重新整理。若沒有更新，在 Apps Script「執行項目」查看錯誤，或手動執行 `refreshWarehouse`；不要刪除舊回應來重試。

贊同姓名現在會出現在可點開的網站名單，滑鼠移到人數可預覽。新版公開資料只帶各願望的姓名陣列 `supporters`，不帶瀏覽器識別碼、回應 ID 或收件時間。舊票沒有姓名仍保留人數。請重新執行 `setupOnce` 更新表單說明，並重新部署最新 Apps Script，網站才讀得到姓名。
